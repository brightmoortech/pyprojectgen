# Replacing an earlier local generator copy

Applies to: replacement of the superseded 0.2.0 layout with the original-module
0.2.1 layout. The obsolete-file instructions below apply only to that transition.
A follow-up 0.2.1 archive also includes pre-commit audit corrections; inspect
CHANGES.md before applying it.

This archive is the complete generator, including all original modules. It
contains no Git history or virtual environment. Replace the generator source
only; it does not replace an existing generated project or its environments.

Before changing a checkout:

1. Check `git status` and the current branch. Preserve existing work in a backup
   outside the checkout, including untracked files. A Git commit alone will not
   preserve ignored files. Keep the original main branch/history available.
2. Extract this archive to a separate directory and inspect `CHANGES.md`.
3. Replace the generator's source and tests from the archive, preserving its
   existing `.git` directory and any environment you intend to retain.
4. Remove obsolete `pgcore.py`, `project_ops.py`, and the earlier `tests/test_cli.py`
   from the checkout only after backing them up. They are not part of this
   original-module-based implementation. Replace the tests directory rather than
   mixing the two test suites. Review all remaining old-only source files.
5. Run `python3 -m unittest discover -s tests -v` and inspect `git diff --stat`
   and `git diff`. If installed through pip/pipx, reinstall the tool through the
   same method; replacing source does not update an independent installed copy.
6. Run the integration suite with `PG_RUN_INSTALL_TESTS=1` on the target Mac.
   The test suite selects the interpreter running the tests for its temporary
   projects. To validate Python 3.12.10, run tests with that exact interpreter.
7. Commit and push the reviewed correction branch after validation. Do not merge
   into main before reviewing its behavior and results.

An existing project generated by a different template version can fail the
initial-template equality checks. Do not delete or overwrite it to bypass those
checks. Review its state separately; this archive does not migrate generated
projects automatically.
